# spec/ — the shared contract

Everything both apps must agree on lives here. Neither app has hard-coded knowledge of an exam.

## Exam presets
- One file per exam: `presets/exams/<category>/<id>.json`, validated by `schema/exam.schema.json`.
- `python3 tools/build_presets.py` validates the schema **and** semantic rules (target inside the
  window with a margin, min < max, high confidence needs an official source or ≥2 sources, …),
  then writes `dist/presets.json`.
- `presets/VERSION` is a monotonically increasing integer. **Bump it with every preset change.**
  Apps refuse bundles with a lower version than the one they already have.
- CI (`spec.yml`) signs the bundle with Ed25519 (`PRESETS_SIGNING_KEY` secret) and publishes
  `presets.json` and `presets.json.sig` to the CDN (`web/`). Both apps embed the public key and a
  build-time snapshot for offline first launch.

### Seed status (2026-09-30)
55 exams: 15 high, 24 medium, 16 low confidence. Known conflicts are written in each file's
`confidence_note` / `notes` (Agniveer, RRB signature, UPSC photo cap, SEBI declaration, CTET signature).
`declaration_text` is `null` everywhere: transcribe it **verbatim** from each official notice
before enabling the declaration helper for that exam (ROADMAP Phase 2).

### Updating an exam when a new notification drops
1. Open the official notice PDF and find the "Guidelines for scanning/uploading" annexure.
2. Edit the exam file: sizes, dimensions mode, dpi, filename, declaration text, `special_rules`.
3. Put the official notice URL **first** in `sources` with `kind: "official"`, and set
   `confidence: "high"` and `last_verified` to today.
4. Bump `VERSION`, then run `build_presets.py` and the fixture tests on both apps.
5. Upload a test file generated by the app to the portal's own validator, where the portal allows it.

### Promoting low → medium/high
A low preset stays hidden behind "Show unverified exams" until someone verifies it against the
live notice. Don't guess numbers.

## Building everything generated from spec/
```bash
pip install -r spec/tools/requirements.txt
spec/tools/build_all.sh              # presets (signed with the public DEV key), strings, tokens, analytics
PRESETS_SIGNING_KEY=<seed> spec/tools/build_all.sh --release   # CI/release: real key, TODO_HI is an error
python3 -m unittest spec/tools/test_tools.py                   # validator + signing-vector tests
```
`spec/dist/` is git-ignored and must exist before either app builds (both embed it). Generated app files
(`strings.xml`, `Localizable.xcstrings`, `Strings.swift`, `ScanFitTheme.kt`, `Theme.swift`, `AnalyticsEvent.*`) **are committed**;
CI runs each `gen_*.py --check` so they can never drift from the spec. Never edit them by hand.

### Strings
`strings/en.json` is the source; every other `<lang>.json` must have the same keys and placeholders (`{count:int}`, `{name:str}`;
a plural is `{"one": …, "other": …}` whose first placeholder is `{count:int}`). A `TODO_HI:` prefix marks an unreviewed Hindi
string: it is stripped from the app, flagged `needs_review` on iOS, and warned by the generator (`--strict` fails). Add a
language by adding `strings/<xx>.json` and listing it in the apps' Info.plist / `localeFilters`.

### Signing keys and the test vector
See `signing/README.md`. `fixtures/signing/vector.json` is run by both apps' unit tests; regenerate it with
`tools/make_signing_vector.py` (deterministic, `--check` in CI).
